APESpace code verification

Check, in your own browser, that APESpace's development and production environments run exactly the same code, and that this code is a release signed by APESpace's official build. Nothing here asks you to trust APESpace's servers: your browser downloads the code and checks it itself.

Downloads about 45 MB from each environment, the same files a meeting loads. Takes 1–3 minutes.

What your browser checks

  1. The release is signed by APESpace's official build. Each release has a signed build record. Your browser checks the signature, that the signing certificate was issued by Sigstore to APESpace's build workflow (OFF-GRID-APPS/APESpace-Jitsi-Meet-WebApp), and that the signature is recorded in Sigstore's public, append-only log (Rekor), so it cannot be quietly replaced.
  2. Each environment serves exactly that release. Your browser downloads every script, WebAssembly module and stylesheet of the release from each environment, as a meeting would load them, and compares their fingerprints (SHA-256) with the signed list. A single changed character shows up.
  3. Development and production serve the same release. So the code you can test on the development environment is the code that runs in production.
  4. The encryption library is the published one. End-to-end encryption is done by lib-jitsi-meet, Jitsi's open-source library, plus a public security patch. Anyone can rebuild it and get exactly the fingerprint checked here (see e2ee-module).

Check your own meeting

This page checks what the servers send to this page. To check the meeting you are actually in, install the APESpace Verify browser extension: it checks every file your meeting loads, and its E2EE Inspector lets you see for yourself that the media is encrypted.

Check it without this page

The same check from the command line (Node.js 20 or later):

git clone https://github.com/hishd/apespace-e2ee-transparency.git
cd apespace-e2ee-transparency
node verify/cli.mjs

Or verify a build record's signature with Sigstore's own tool:

cosign verify-blob \
  --bundle releases/<release>/builds/<record>.json.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/OFF-GRID-APPS/APESpace-Jitsi-Meet-WebApp/\.github/workflows/build-docker-image\.yml@refs/heads/(develop|main|master)$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  releases/<release>/builds/<record>.json

What this does and does not show

  • It shows what each environment serves to you, at the time you check.
  • The meeting page is compared too, for releases whose pages are static files: those pages carry a security policy that lets only the release's own scripts run, and read the server's settings files (config.js, interface_config.js) as data. The settings files themselves are generated by each server and are not compared. Images, fonts and sounds are skipped.
  • The rest of the APESpace app is not open source. This check proves every environment runs the same signed release; it does not show what that code does. The encryption library is the part you can rebuild from source.
